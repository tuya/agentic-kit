01空间总览

这是涂鸦 AI 空间音频产品线的研发方案库，覆盖三条硬件线——入门版耳机（普通 BT 耳机不换硬件，靠 App + 云端获得 AI 能力）、Pro 耳机（涂鸦蓝牙模组，BLE 传 Opus 流）、AI Note 录音卡片——以及 AI Note / AI Translate 两个小程序、PC 桌面端与云端接口。方案主体是客户端（iOS / Android / 小程序），同时涉及固件、硬件与协议定义。

03核心技术域

同一条链路的知识散在多个版本里。这里按六个技术域横向归拢：每一域给出主干脉络与关键文档入口。

音频链路与编解码

整条链路是「采集 → 3A → VAD → 编码 → 上行」，各环节都有独立方案且持续迭代：

  • 采集：入门版手机 mic / BT、Pro 耳机 Opus 流、卡片与 Note 离线录音；iOS 26 收音质量启用蓝牙高质量录音与远场输入两项系统新能力（需灰度开关回滚）；Android 音频控制分析弄清了并发录音静音仲裁——与 hey tuya 抢麦时被静音的那一路读到的是全零帧。
  • 3A 与回声：AEC / ANS / AGC 全链开启（AI 音频解决方案总图）；2.3.5 引入 DTLN 治同传 / 面对面翻译的回声消除丢字与安卓碎片化。
  • VAD：WebRTC GMM 起步（端侧 VAD 方案：四态状态机、句首 1.2s 预缓存、15s 预警 20s 硬切）→ 动态阈值 → Silero 模型接入（1.8M 异步加载、失败降级 webrtc、iOS 因准确率暂缓上线）→ v3.1 规划 C++ 统一实现（空壳页）。
  • 编码：msbc 7.5ms 帧双编码器交叉（msbc 方案）；Opus 调优（16k 采样 / CBR / voip 模式）；PCM→MP3 从 96K 降 64K 无明显损失；转码从单文件串行 → 按帧边界分片并行（Android / iOS 批量化读取 → v3.1 双端共享 C++ 引擎）。
  • 上行：发包 20ms/帧 → 5 帧合包降频（1.8 双端性能）；设备侧 N×40/N×80 合并治嵌入式 RAM 跑满死机；弱网大文件改 HTTP 分片 + 断点续传。

转写 · 翻译 · 总结

面向小程序的 TTT 接口族是这条产品线的业务 API 中枢，几乎每版都在增改：

  • 演进脉络：v1 全套录音控制 + 转写 API 正式文档（30s 上限、2s 限频、两套错误码）→ v2.2 开启接口换血（audioSource / needAsr / updateParams，TTT Api 修改）→ v2.3 转写翻译与说话人分离入参 → v2.5 分页 / 直播 / Token 预申请 → v3.1 标签四接口 → v3.4 回收站分组。
  • 流式翻译 2.0：根因是 Native-JS 通信频率，ASR 事件携带 translateText 合并下发，翻译刷新由尾部追加改覆盖；文本翻译把每次翻译虚拟成独立录音任务复用整条链路。
  • 播报侧：朗读译文设计 TTSConfig + ITtsPlayer 摆脱 1v1 限制；TTS 提前播放分块流水线压首响时延；云端 TTS 从 MP3 扩展 ogg（AI 基座 2.0）。
  • 云端转译用 Whisper 与 Google STT v2（chirp_2），LLM 翻译 65+ 语言（AI 音频解决方案）。

文件管理与云同步

录音文件从设备到云的完整生命周期，每段都有专项：

  • 取回：v1.0 蓝牙大数据通道（串行断点续传）→ v1.5+ 透传协议（TLD 文件列表）→ AP 热点快传（UDP，效果优化与 iOS 错误码 10300-10305；Android 12+ 连接改造）。
  • 转码入库：Opus→MP3 后写库，v3.1 起分片并行；两篇代码级文档（iOS / Android，2026-04 新增）与 跨端对比分析（20 项功能矩阵、一致性 4/5）把现状风险列全。
  • 云同步（v2.4 总案 + 上传下载细化）：五表结构、账号级开关经 MQ 广播、每用户独立云空间密钥、音频 AES-CBC-256、md5 校验、extAttribute 64 位位图记录上下行状态、错误码 10200-10212。
  • 整理：文件合并（MP3 掐头去尾 + 云端合并转写结果）、标签与搜索（云端四接口 + MQTT 回拉）、visit 已读未读四态、删除与音频清理、v3.4 回收站 30 天软删。

设备交互与 DP 协议

设备侧协议集中在少数几个 DP 上，但语义一直在加厚：

  • record_control（dp63）：cmd + format + type + flag 四段十六进制；cmd 从 0~4（app 侧控制）扩到 5/6（设备侧发起）与 3/4（手机耳机 / 电话翻译模式）。
  • record_interrupt（dp62）来电中断；buds_mode_switch（dp65/66）TWS / 1v1 切换，随机数校验 + 主从耳 UUID；ai_mode（dp67）meeting / phone 供面板监听；卡片离线录音状态 DP（none/meeting/call）。
  • 通道迁移：v3.2 起电话录音 / 通话翻译的 DP 收发从 BLE 迁往 SPP（Android）/ EDR（iOS）；iOS BR/EDR 方案为带宽不足重构了电话翻译链路。audioSource 枚举分段：系统 0-19 / 耳机 20-39 / 卡片 40-59 / 导入 60-63。
  • 能力判定从 dpcode 改为 iot 平台高级能力打标，避免与其他产品 dpcode 冲突；AI Voice 通用 DP 协议把这套协议推广到耳机 / 录音板 / 眼镜 / 玩具等音频输入类设备。

平台与入口

  • 小程序：TTT API 是主接口面；静默监听硬件 DP、预加载与 uniqueCode 路由、无网络收口、v2.3 拆分 AI Note / AI Translate。
  • 首页卡片：quickWidgets（1.8/v2.1）→ 大卡片拆分耳机笔记 14 / AI 翻译 18（v2.3）→ 跳转链接改 thingSmart://miniApp?uniqueCode= 并加 utm 埋点（v2.7）。
  • 系统外显：iOS 灵动岛 / 实时活动 + 通知卡片 + 悬浮按钮（v2.8，含两篇打包与描述文件规范）；Android 实时通知（targetSdk31 限制与 Android 16 实时更新）+ FloatingX 悬浮框。
  • 快速启动（v2.9）：iOS App Intents / Siri / 聚焦 / 控制中心（iOS 18+），Android 磁贴，TTT getQuickEntryList；异常分支（已录音 / 未登录 / 设备离线切手机）逐项定义。
  • PC 端（v2.9，8 篇）：Electron + Vite、Tray 控录音、WASM 基座 2.0 实时 ASR、MIC + Loopback 双路收音（macOS ScreenCaptureKit / Windows WASAPI）、实时字幕悬浮窗、Forge 打包与签名公证、autoUpdater 覆盖安装。

04专题与调研

翻译形态的探索

同声翻译调研（2024-05，空间最早的文档）对比了双耳各一 / 外放 / 单耳分戴 / 远程通话四种形态，结论是需要耳机主从标识 + 声纹辅助。此后按形态逐个落地：同传（v1.4）、面对面翻译（v2.1）、手机-耳机模式（v2.5）、电话翻译预研（v2.5）→ BR/EDR 方案（v2.9）→ DP 迁 SPP/EDR（v3.2）。AirPods 离线翻译调研的结论是技术成本高（单语言模型约 1GB）、短期不建议跟进——为「不做」留下依据。

竞品与行业

竞品分析有固定 模板（五维度 × 三方对比表）。已完成的专题：AI 录音卡片（Plaud Note 开创品类、TicNote 主打内容创作者、钉钉 A1 绑企业生态；涂鸦短板是 Ask AI 与云同步）、AI 眼镜（框架稿）、豆包耳机（经典蓝牙 + MPI 心跳拉起 App）、竞品安全合规（五款竞品普遍缺 GDPR / CCPA / 儿童隐私条款——反衬自研合规优势）、Plaud PC 登录（auth_code 三段式，自研 PC 端直接参考）。

技术底座

AI 音频解决方案是唯一的全景架构文档（设备 + App + Cloud 三层、3A/VAD/ASR/翻译/TTS 全链路、业务模式矩阵），新人先读这篇再进版本线；配套 ASR 基础知识（AM+LM+解码、采样率计算、麦克风阵列）。AI 眼镜技术储备（2025-10）把主控芯片、光波导 / Micro OLED、边缘-中心云协同、跨端框架到安全合规梳理成册，是下一条产品线的预研底稿。

产品与商业化

产品体验汇总记录了客户与供应链事实：入门版客户含新画面 / 砂糖 / 倍思 / SBS，原厂杰理，云端早期仅部署美区；竞品参照讯飞 Nano+、时空壶 W4 Pro、PLAUD Note（交付 30 万台）。项目梳理区分两条产品路径——Pro 版换涂鸦蓝牙模组走 BLE Opus 流，入门版零硬件改动扫码激活。Tuya Fit 公版权衡后倾向合入公版走 OEM 配置而非独立 App；AI 效率小程序与 其 Android 优化记录了不依赖耳机的纯手机转写翻译形态。
